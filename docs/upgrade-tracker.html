Current priority

Prove that every daily download is complete.

Initial checks established valid JSON and matching declared counts. A deeper audit found that valid JSON can still omit database records. Export completeness now takes precedence over adding event features.

Repaired in production: September 8 now has 1,031 CVEs (previously 10); September 15 has 982 (previously 5). Exact exported article/CVE ID sets match the database on both days.

Deployed: complete-day serialization, uncapped CVE downloads, suppression filtering, dependency fingerprints, and locked atomic archive writes. The first build refreshed 38 dates and retained all 5,059 files; 5,021 files retained identical bytes and timestamps.

Read-only production evidence: inventory of 5,084 database dates took 0.40s; uncapped selections returned 1,031 and 982 unique CVEs in 0.14s and 0.06s. These timings exclude serialization and publishing.

Availability: 85 public samples found no outage; homepage, metrics, search, and representative downloads passed. No new build-host OOM events; Kubernetes/etcd readiness passed.

Bounded repair enabled: only the builder repairs up to one historical date per refresh; all other workers retain limit 0. August 15 recovered 553 missing CVEs, with exact IDs matching the database. First pass retained all 5,059 files and 5,057 unchanged hashes/timestamps. The next automatic build advanced the backlog again. Full historical repair is still in progress, not complete.

Preparation incident: a rollback snapshot was mistakenly placed in Hugo's /data input and caused one pre-rollout build failure. It was moved to /log before validation; the prior published release remained live. No database backup or recurring backup task was added.

Release invariants

  • Existing site and last validated output stay available throughout upgrades.
  • Downloaded JSON is an external API: preserve paths, identifiers, field types, dates, score units, missing values, and both News/CVE records.
  • Reuse unchanged history outside Hugo's loaded data path. No full-history rebuild on normal publication.
  • Build and publish through the platform API. No direct Hugo invocation.
  • Use the existing model and single-job queue; additions must fit measured spare capacity.
