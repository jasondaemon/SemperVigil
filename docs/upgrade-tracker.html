Current priority

Prove that every daily download is complete.

Initial checks established valid JSON and matching declared counts. A deeper audit found that valid JSON can still omit database records. Export completeness now takes precedence over adding event features.

September 8: database inventory 1,031 CVEs; public download 10. September 15: inventory 982; download 5. The running exporter can overwrite a day from a limited recent selection; attribution of each existing discrepancy is still under investigation.

Verified locally: recent-day exports now use the full-day serializer without the 500-CVE cap, honor article suppression, and reuse unchanged files. The historical article ID alias is retained. Atomic replacement and a 1,031-CVE fixture pass. No production deployment.

Read-only production evidence: inventory of 5,084 database dates took 0.40s; uncapped selections returned 1,031 and 982 unique CVEs in 0.14s and 0.06s. These timings exclude serialization and publishing.

Next: reconcile recent local-date bucketing with archive date selection, verify enrichment invalidation and CVE-only behavior, then measure complete export cost before a bounded API-driven rollout. Historical repair has not run.

Release invariants

  • Existing site and last validated output stay available throughout upgrades.
  • Downloaded JSON is an external API: preserve paths, identifiers, field types, dates, score units, missing values, and both News/CVE records.
  • Reuse unchanged history outside Hugo's loaded data path. No full-history rebuild on normal publication.
  • Build and publish through the platform API. No direct Hugo invocation.
  • Use the existing model and single-job queue; additions must fit measured spare capacity.

2 / Evidence and incident correctnessPlanned
  • Claims linked to sources and passages, with uncertainty and date precision.
  • Incident-aware matching; repeated breaches at one organization remain separate.
  • Independent evidence assessment, immutable revisions, and correction history.
  • Reject malformed reports and unsupported dates; preserve stable public URLs and last validated reports.

Exit: evaluation cases reject cross-incident contamination, invented chronology, and untraceable claims. New path remains gated until tested.

3 / Small shadow pilotPlanned
  • 5-10 events with dedicated extraction/report profiles using the existing model.
  • Bounded context and output; deterministic matching and report structure; cache unchanged evidence.
  • Provisional 10% inference-time ceiling, dependent on measured spare capacity. No parallel calls or automatic cloud fallback.
  • Review private output before publication; retain deterministic reports if prose quality is inadequate.

Exit: correctness cases pass and seven days show no new latency/resource regression. Pause admission when fresh-content budgets are exceeded.

4 / Living Events in productionPlanned
  • What happened, what changed, cited milestones, impact, mitigation sources, and uncertainty.
  • Connect Events to daily JSON and search without recreating CVE detail pages.
  • Publish changed event inputs only; repair existing events in bounded batches.
  • Verify desktop/mobile presentation, source citations, revisions, and existing URLs.

Exit: compatible downloads and tested publication; last validated pages survive generation failures.

5 / Reader features and audioPlanned
  • Changes since last visit, event feeds, browser-local watchlists, and compact incremental search.
  • Evidence-backed disclosure/patch/exploitation intervals and KEV/EPSS history with coverage caveats.
  • Listen to the news: one Play button, continuous summaries, pause/resume, skip, speed, and saved position.
  • Trial browser speech using existing JSON with no new LLM work. The daily player can follow Stage 1 independently of Events.
  • Test screen lock, Bluetooth, navigation prompts, and calls on physical iPhone/Android devices. Evaluate cached audio/podcast delivery if browser speech is unreliable.

Exit: demonstrated reader utility and acceptable operational cost. Do not call audio driving-ready before device tests pass.

6 / Monetization readinessLater
  • Publish methodology, attribution, corrections, automation disclosure, and privacy information.
  • Evaluate AdSense after content demonstrates original value; automated checks do not constitute human review or guarantee approval.
  • Consider genuine editorial curation for ad-bearing content, or sponsorship and paid alerts/data access if publishing stays fully unattended.

Success means useful, trustworthy coverage. AdSense approval is not a prerequisite for delivering Events.
